# Leaf5+ 墨水屏开发路线图

更新：2026-10-26。分支：`feature/leaf-eink-adaptation`。同步时源码基线：`9244f128143409310c086910d552d3beeaec3e52`，已包含分段底栏及ARM64工作流。最新公开版为Leaf 1.18.2 / 2402；下文2382是此前的体验基线记录，设备当前版本待用户确认。此前调研基于 `3eac32b`，重新对照前先记录实际安装版本。本分支 = main + 墨水屏调研文档，墨水屏功能尚无运行代码。

目标：黑白界面清楚、操作及时、动态变化少；保留漫画灰阶、既有数据和紧凑底栏；新改动不引入明显耗电回归。设计与评审先读[官方 SDK 核心约束](LEAF_EINK_GUIDELINES.md)，底层细节按需查索引。

## 顺序、依赖与交付

| 阶段 | 工作与顺序逻辑 | 完成条件 | 当前状态 |
|---|---|---|---|
| 1. 建立基线 | 固定包、设备设置和短操作序列，记录现有问题，避免把系统模式变化误当成优化 | 确认运行版本、关键设置、固定阅读样本及问题优先级；耗电观察建立入口并标注缺失项 | 2382 已核验，用户确认安装；等待设置与操作反馈 |
| 2. 黑白 UI | 共享主题/控件 → 首页书架详情设置 → 阅读菜单 → 硬编码颜色；先保证最终画面清楚 | 常用状态不依赖颜色可辨认，漫画原图未被改变，底栏参数保持；对照外观可恢复 | 待实施 |
| 3. 减少动态效果 | 先转场/菜单/封面/加载，再分别核对点击、实体键、手势翻页；保留必要滚动缩放 | 反馈及时，快速连按/取消/返回不失效，加载与失败状态明确；无新增持续动画 | 待实施；完成后可交付第一版 UI 体验包 |
| 4. SDK 最小验证 | 官方依赖和能力探测 → 一次手动刷新 → 系统模式冲突、退出恢复和 Flutter 时序 | 实机确认请求有效，失败有结果，能关闭/恢复；不能只以“未抛异常”验收 | 待实验；可在阶段2–3期间独立推进，不默认开启 |
| 5. 自动刷新策略 | 只有阶段4通过且仍有残影需求才做；合并同一操作请求、取消过时请求，再调触发条件/间隔 | 残影收益可见，额外闪屏/延迟可接受，不与系统及原软件闪屏重复触发 | 待阶段4及实测结果，不预定每N页 |
| 6. 能耗与默认值收敛 | 各阶段持续检查耗电风险，最后固定场景比较并决定默认值；按证据调整预加载/轮询 | 显示与交互通过，耗电结果可解释；证据不足的硬件策略保持可选并标注待验 | 持续约束，最终实测未开始 |

主线为 1 → 2 → 3 → 体验包。阶段4早验证、晚启用，不阻塞不依赖硬件接口的 UI 改进；阶段5必须等4实机通过。系统刷新足够时保留系统策略，不增加自动全刷。

## 第一阶段的分工与结果

- agent：核对当前源码、包身份与已有测试记录；准备简短操作清单；整理用户反馈，确定阶段2/3先解决的页面及路径；维护对照条件。此次不新增运行代码、定时任务或采集工具。
- 用户：先记录当前实际安装版本，再做一次约5–10分钟检查（此前2382记录保留作历史对照），提供设备设置及问题现象。无需 root、ADB、重新安装或导入数据。
- 必需输入：固件和当前系统刷新模式（找不到可标未知）、阅读动画/软件闪屏开关、选定章节及起始位置、操作后的主要问题。步骤及可复制反馈格式见[第一阶段基线记录](research/2026-10-26-eink-baseline.md)。
- 耗电初始记录可随正常阅读后补，不阻塞黑白 UI 实施；基线记录不完整时，后续不得宣布耗电验收通过。阶段1只记录原状态，不选“最佳刷新模式”，不同时调整多个变量。

收到短测结果后，将问题整理为“页面/操作—现象—优先级—验证方式”，更新阶段2/3范围；读取不到的固件参数继续标未知，不猜测。残影靠拍摄屏幕或用户描述，应用截图只用于检查布局。

## 耗电约束与可验证承诺

目标是同等使用条件下不出现可重复、超出测量波动的耗电回归。实测前不承诺零增长，单次短测1%变化不作结论。当前阶段仅写文档；后续每项功能单独说明可能增加的工作。

开发中采用以下约束：

1. 不为墨水屏适配增加周期性全刷、常驻保活、高频电量/设备状态轮询；静态页面不因新功能主动反复提交画面。
2. 硬件刷新按有效事件触发；合并重复请求，处理快速翻页、取消、退出和休眠，避免过时任务继续刷新。后台不因新增功能继续工作。
3. 图片预加载、缓存及现有时钟/电池逻辑在无测量依据时不顺带改动；黑白 UI 不以持续全屏滤镜或逐帧图像处理实现。
4. 调试日志与采样按需启用、有结束条件；不以新增常驻监控证明省电。去掉动画是否省电待实测。
5. 新 SDK/插件依赖同时核对包体积、启动及后台行为。引入 SDK 不默认开启自动刷新；若发现可重复耗电回归，先定位、减频或关闭相关策略，再决定是否交付为默认。

耗电验证分两层：先检查上述运行行为，再做同条件真机对照。实测固定设备、固件、系统模式、前光、网络、缓存状态、内容和操作节奏，记录起止时间、电量及中断。阅读期间不充电；首次下载/索引、温度变化、录屏或其它后台活动应标注，避免混入正常阅读耗电。

正常阅读60分钟作为首次采样窗口。仅有整数电量且几乎不掉电时记为“不足以判断”，需更长窗口或复核；出现差异再重复对照。记录“电量下降百分点/小时”，小时内1个百分点的差异不换算成耗电百分比。休眠耗电与主动阅读分开记录。

有可关闭功能时优先在同一测试包里比较开/关，便于隔离增量；SDK 常驻开销需另与旧源码基线包对照。若需重打旧源码基线，仍使用固定签名并递增版本码，避免要求用户卸载或强行降级APK。测不清楚时保持“待验”。

## 迭代与交付规则

每次只引入可归因的一组变化，复用现有设置及全局/设备/单漫画作用域，不为每个动画增加独立开关。新增默认值和旧设置迁移需明确，不能悄悄覆盖用户已有选择。主题、动画、硬件实验和自动策略按实际改动分别验证、组织提交。

测试包持续使用同一 Release 包名、同一签名、ARM64 ABI和递增版本码；截至本次同步已公开版本码2402，后续构建前重新核对。覆盖更新保留数据，避免来回切Debug。UI布局/交互自动验证与硬件/耗电实测分别报告。推送及公开发布遵循当次授权。

进度与实测证据追加到[调研目录](research/README.md)，不将用户的私人漫画或设备标识默认纳入公开仓库。
