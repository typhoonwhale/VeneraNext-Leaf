# Leaf 1.19.1：章节已读、看过与手动标记

本功能在 `feature/leaf-read-state` 开发，基于已发布的 1.19.0。1.19.1 当前尚未发布；本地专项已通过，实机与完整 Linux CI 仍待验，具体范围见下文。当前正式版与分支用途见[状态说明](LEAF_STATUS.md)。

## 用户可见行为

章节有三种状态：未读不显示符号；打开过但未读完显示空心圆；达到完成条件或手动标为已读时显示勾。旧版本留下的已读记录保留，升级不自动纠正过去的误标。

“上次读到”是独立的位置状态。墨水屏仍以黑底白字突出该章节，同时用白色粗勾或空心圆表示是否完成；普通模式用底色和粗体突出续读位置。漫画正文和已有续读页码不受这些标记影响。

长按章节格子（桌面端右键）可标为已读、标为未读，或将同组之前的章节标为已读。标为未读会同时清除看过；“之前”按阅读顺序计算，不受列表倒序影响，不包含当前话，也不跨越分组。没有历史记录时可以手动标记，会创建没有续读位置的历史条目；已有条目的时间、章节和页码不因手动标记改变。

## 自动判定与续读

- 以源图片编号累计正向经过的图片，重复往返不重复计数；常规章节需显示过末张，并正向经过至少一半图片、下限 3 张。
- 初次定位、拖动进度条、章节菜单跳转和布局重排不直接产生正向阅读证据。正常前翻离开章首首屏时，可计入该首屏中第一张之后的图片，以支持双页完整阅读；只打开或跳页不会得到这项证据。
- 1–3 张图的短章需要完整显示应读图片，再主动向前越过末尾。仅回翻进入上一话末页只记看过；若上一话只有一张图，之后真正前翻离开才记已读。
- 同一阅读会话内保留累计证据。恢复已有“看过”章节的保存位置时，补计保存页之前的图片；这是已确认的续读补偿。旧记录不能证明此前是否跳页，因此此前跳过的图片可能被补计，这是明确接受的边界。
- 连续和瀑布流模式把实际可见图片与“当前续读页”分开处理，避免短末张始终不是最大可见图片而漏判。加载占位不作为末张已显示的证据。

## 数据与兼容

`history.db` 新增可空文本列 `viewedEpisode`，键格式与 `readEpisode` 相同：普通章节为 `"3"`，分组为 `"2-3"`。打开旧库时按列存在性补列，NULL 按空集合读取，重复初始化安全；显示时已读优先，继续识别旧分组数据中的扁平键。

备份和同步仍使用整份数据库快照。旧库导入后补列；当前实现的旧 Leaf/VeneraNext UPDATE 不覆盖新列。已核查的历史 Venera 使用整行 REPLACE，会清空被重写行的看过数据；未宣称已验证所有最新上游版本。旧客户端也仍可能按照“加载即已读”追加已读记录。

模型的 `copy()` 包含新集合。阅读器继续使用既有 `ReaderHistoryWriter` 合并写入，退出/挂起时 flush；未增加轮询或新的周期计时器。手动标记执行时读取最新历史并复制，写入成功后刷新界面。保存期间统一阻止章节、继续阅读及缩略图入口打开阅读器，避免旧历史快照覆盖刚保存的标记；失败时保留旧界面状态并释放入口。
