## 后续 agent 从这里开始

1. 核对当前分支、commit、tracking upstream和工作区状态。main 为主线，功能用独立 feature 分支；早期记录基于 `feature/leaf-reader-footer` / `77e12cf9b09e177b501fb5a7ab45ce58c07d8721`（已合入 main），以实际checkout为准。
2. 读本索引及相关主题，再查源码。目标机型是Leaf5+；使用者确认手势导航、无底部虚拟按键栏。手机安全区、DPI或其他BOOX机型参数需有依据才可套用。
3. 区分证据来源：官方通用文档、用户报告、widget截图、实机截图、构建验签、安装迁移升级结果，分别标注。
4. 沿用固定Release包名和签名。不要生成新密钥替代现有密钥，不要将Debug直接当作Release升级基线；如需重新构建，先读构建说明并核对已交付最高versionCode。
5. 完成改动后按影响验证，把结果和未验证项补入新记录。正式修改README中的能力描述时，说明实现、自动验证和实机确认分别到哪一步。

## 新调查如何记录

- 文件名用 `YYYY-MM-DD-主题.md`；同一调查继续更新原记录，新增主题再建文件。每次增加记录后更新上表，并从相关方案链接到它。
- 记录最少包括：问题与目标机型、调查日期、源码分支/commit与工作区状态、来源链接及关键原文、观察到的参数及单位、结论与实现影响、验证方法及结果、待核实项。
- 对关键事实标注“官方说明”“用户确认”“源码核对”“本地自动验证”或“待实测”。保留被修正的旧假设及修正原因。
- 小型且可公开的原始证据放 `evidence/` 并链接：例如脱敏的包身份JSON、公开证书指纹、相关日志节选。记录采集方法；没有保存原始材料时明确说明，不伪造快照。
- 本目录不保存keystore、密码、Cookie、账号、私人漫画数据或带凭据的网络日志；大体积APK和完整构建缓存不入库。需要包文件时通过已发布产物或可信交付入口取得，并用记录中的SHA-256核对。

记录是历史依据，当前状态以源码和设备为准。提交、推送和设备操作遵循当次用户授权及仓库约定。
